微博文字导出器 0.4.0（pre-1.0）
=================================================================

当前公开版本已经通过 Windows 验收。
本版本为经过严格证明、当前无法验证的历史长微博增加显式不完整归档语义。

【这版最重要的变化】

V6.6.2：
GUI
→ 下载 weibo-crawler
→ pip install 一组依赖
→ subprocess 启动第三方 crawler
→ JSON
→ Markdown

当前版本：
GUI
→ 我们自己的 WeiboClient
→ parser
→ frozen dataclass
→ Markdown

也就是说，导出阶段已经不再：
- 从 GitHub 下载 weibo-crawler
- pip install crawler requirements
- 启动第三方 Python 抓取子进程
- 依赖 requests / lxml / Flask / MongoDB / MySQL 等 crawler 依赖
- 调用浏览器 / Chromium / Playwright / Selenium

二维码登录仍使用 V6.6 已跑通的内置微博 QR SSO。

------------------------------------------------
建议第一次这样测试
------------------------------------------------

1. 双击 CHECK_ENV.bat
   应看到 RESULT: PASS。

2. 可以双击 TEST.bat
   应看到 46 项 [PASS] 和：
   ALL V7 TESTS PASSED

3. 双击 微博文字导出器.pyw。
   这是普通 GUI 入口，不会保留 CMD 黑窗口。

   如需诊断启动问题，可从 CMD 运行：
   python -m weibo_archive.app

   START.bat 也保留为带控制台的诊断入口。

4. V7 与 V6 共用：
   %LOCALAPPDATA%\WeiboTextExporter\cookie.txt

   所以你在 V6.6.2 已登录过的话，V7 通常会直接显示“已保存登录状态”。
   如果失效，点“扫码登录 / 更新”即可。

5. 输入要备份账号的数字 UID。

6. 在“导出内容”中选择完整归档（推荐）、AI 精简或自定义。
   自定义可以选择排版、来源/设备、发布位置、转评赞和日期格式；
   正文与日期始终保留。

7. 第一轮强烈建议先点：
   [ 试抓 50 条 ]

   先检查：
   - 用户名/简介
   - 时间
   - 正文
   - 转发原文
   - 图片/视频数量
   - 转评赞
   - Markdown 是否正常

8. 50 条没问题，再测试：
   - 最近 1000 条
   - 从某日期起
   - 全量快照

------------------------------------------------
V7 的范围语义
------------------------------------------------

全量快照
  默认。抓到接口明确的自然终点。

最近 N 条
  新→旧抓取，达到目标后提前结束。
  置顶旧微博不计入普通时间线候选，也不会污染抓取进度。

从 YYYY-MM-DD 起
  新→旧抓取。
  连续确认进入起始日期以前后停止，避免单独一条旧置顶微博误触发结束。

试抓 50 条
  用于快速确认 UID / Cookie / 网络 / 解析 / Markdown。
  输出文件名明确包含“试抓50条”，不会伪装成完整备份。

暂时没有“任意历史起止区间”。
因为列表只能从新往旧遍历，选择很久以前的一小段并不会让请求明显变快。

------------------------------------------------
文件名
------------------------------------------------

当前版本每个任务只生成用户所选的一份主 Markdown，不会自动同时生成所有版本。

全量示例：
用户名_UID_全量快照_截至YYYYMMDD_完整.md
用户名_UID_全量快照_截至YYYYMMDD_AI精简版.md
用户名_UID_全量快照_截至YYYYMMDD_自定义_完整.md
用户名_UID_全量快照_截至YYYYMMDD_自定义_AI精简.md

最近示例：
用户名_UID_近1000条_完整.md

日期示例：
用户名_UID_20240101起_AI精简版.md

试抓示例：
用户名_UID_试抓50条_自定义_完整.md

文件头还会写：
- 导出范围
- 抓取终止原因
- 快照时间
- 本次输出配置

导出完成后会出现“打开文件”“打开导出文件夹”“关闭”。
程序不会自动打开文件或文件夹。

------------------------------------------------
“备份可信”规则
------------------------------------------------

V7 宁愿明确失败，也不静默生成看似完整的坏备份。

例如：
- 同一条长微博的两条全文路径都明确返回当前无查看权限 → 标记为不完整，预览不冒充正文
- 长微博出现混合、未知、网络、认证、结构或 ID 不一致结果 → 失败
- API 返回验证码/风控卡片 → 失败
- API 返回非空但未知结构，无法证明已经自然结束 → 失败
- 除上述严格白名单外，网络返回 HTML 而不是预期 JSON → 失败并给出可操作提示

不会把这些情况当成“抓完了”。

------------------------------------------------
运行详情
------------------------------------------------

主界面默认保持简洁。
“运行详情 ›”默认折叠；需要诊断时再展开。

抓取时会显示：
- 已抓微博数
- 页数
- 最早到达日期
- 当前阶段

------------------------------------------------
缓存
------------------------------------------------

V7 会保存标准化缓存：

%LOCALAPPDATA%\WeiboTextExporter\v7_cache\<uid>\last_success.json

它：
- 使用 schema_version 1
- 不含 Cookie
- 不含请求头
- 不保存图片/视频 URL
- 包含微博正文及明确标记的 timeline 预览

所以它仍然属于个人归档数据，请像 Markdown 一样保护。

------------------------------------------------
0.4.0 仍然没有做的事
------------------------------------------------

1. 最终 EXE
   当前版本仍需要电脑已有 Python 3。
   等独立抓取核心通过真机验证后，再做 PyInstaller onedir。

2. DPAPI
   当前版本为了兼容 V6 已有登录状态，仍使用明文 cookie.txt。
   正式版计划迁移 Windows DPAPI。

3. 断点续抓
   全量抓几万条时，如果中途中断，目前仍需重新开始。

4. 增量更新
   数据模型已为后续实现留好边界，但当前版本不做。

5. 安装包与签名
   PyInstaller onedir、安装器和签名留待后续阶段。

------------------------------------------------
遇到问题
------------------------------------------------

可以发送：
- 截图
- GUI 运行详情
- %LOCALAPPDATA%\WeiboTextExporter\last_error.txt

不要发送：
- cookie.txt

如果是“某条微博内容不对”，最好同时说明：
- UID
- 大致发布日期
- 是原创还是转发
- 是否长微博/图片/视频

不要发送任何登录 Cookie。
